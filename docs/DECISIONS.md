# Decisions

A short log of decisions (ADR style). Most recent at the end. Format: **date · decision** — reason.

The library's folder names were in Portuguese until 2026-10-25 (`Livros/`, `_a revisar/`, `_Sem editora/`, `_importados/`); the older entries keep those names, and the 2026-10-25 entry records the switch to `Books/`, `_To review/`, `_No publisher/` and `_imported/`.

- **2026-10-17 · Our own desktop app instead of Calibre.** Calibre does much more than needed and lacks the comics workflows (collected editions, Komga, Kindle).
- **2026-10-17 · C# + .NET 10 + Avalonia 11.** The user knows C#; it is cross-platform (Linux in the future) and lightweight. Electron and a web app were ruled out.
- **2026-10-17 · Name Gibi-o-matic; MIT license.**
- **2026-10-17 · No migration from Calibre.** The user is downloading all the originals again; the metadata will be redone.
- **2026-10-17 · Archive: the files on disk are the source of truth.** One `metadata.json` per book; the SQLite index is only a rebuildable cache and lives **outside** Google Drive, because SQLite in a synced folder gets corrupted.
- **2026-10-17 · Immutable originals.** Metadata is never embedded in the original; it lives in `metadata.json` and in the destination copies.
- **2026-10-17 · Preferred formats for the main original: CBZ > PDF > EPUB > CBR.**
- **2026-10-17 · Configurable "Destinations"** (Komga, Kindle; others in the backlog), each with "which books" and "when" rules and a hidden "Advanced".
- **2026-10-17 · Komga: `{Series}/…` by default, without a publisher folder; one-shots folder configurable in the destination** (default `_oneshots`).
- **2026-10-17 · Automatic metadata approval on, with strict rules** (SPEC §8.2) and a mark for spot checks.
- **2026-10-17 · Books that aren't comics: an option per destination**, according to the type's capabilities. Komga yes (reflowable EPUB); Kindle to do.
- **2026-10-17 · No AGPL/GPL dependencies.** PDFium and PdfPig instead of MuPDF.
- **2026-10-17 · Kindle via KCC called as an external process**; delivery over MTP on Windows; Linux to do.
- **2026-10-17 · F0: Avalonia 11.3 (not 12).** ~~Avalonia 12 is already out, but the recorded decision is 11.~~ Superseded by the decision below, from the same day.
- **2026-10-17 · Tests with xUnit v3 on Microsoft.Testing.Platform** (`"test": { "runner": ... }` in `global.json`). The .NET 10 `dotnet test` no longer accepts VSTest with xUnit v3. Command: `dotnet test --solution GibiOMatic.sln`.
- **2026-10-17 · Static fonts, not variable.** Avalonia 11 doesn't select axes of variable fonts. Bricolage Grotesque comes from the author's repository (ateliertriay/bricolage), IBM Plex Sans from IBM/plex and IBM Plex Mono from google/fonts.
- **2026-10-17 · `gibiomatic-library.json`** = `{ formatVersion, id, createdAt }`. The id is a ULID generated by our own code (no package); the book's short id is the ULID's last 6 characters, lowercased.
- **2026-10-17 · SQLite index**: numbered migrations through `PRAGMA user_version`; an index written by a newer app version is discarded and rebuilt (it is only a cache). Connections without *pooling*, so the file is released right after each operation.
- **2026-10-17 · Opening a library recreates `Livros/` and `.gibiomatic/` if they are missing**; it never touches the books. Creating is only refused if the folder already holds a library.
- **2026-10-17 · `settings.json`**: unknown keys (from newer versions) are preserved on save; an invalid file is copied to `settings.json.bad` and the app goes on with the defaults.
- **2026-10-17 · Secrets**: one file per secret in `%APPDATA%\GibiOMatic\secrets\`, encrypted with DPAPI (current user). On Linux, a *stub* that stores nothing (libsecret to do).
- **2026-10-17 · Interface text**: `Strings.resx` (pt-BR, neutral culture) and `Strings.en.resx`, with a class generated by MSBuild and used through `x:Static`. Changing the language requires restarting the app.
- **2026-10-17 · Migration to Avalonia 12 (12.1.4).** At the user's request, before F1, while the interface is still small and the switch is cheap. 12.0.0 has been stable since 2026-04-07. None of the breaking changes listed in the official guide affected the F0 code: a build with no warnings, green tests and screens identical to 11's.
- **2026-10-17 · F1: manual import in two steps (user decision).** Dragging or choosing files only puts them in the Inbox, already analyzed (format, SHA-256, embedded metadata, cover, duplicates), without writing anything to the Archive. The copy happens after "Import". It is the "dry run, confirmation and log" rule applied to import.
- **2026-10-17 · F1: the source file stays intact (user decision).** Manual import only copies; moving to `Inbox/_importados` is left for the automatic inbox (F5).
- **2026-10-17 · F1: "Replace the current one" uses an internal trash (user decision).** The original that leaves goes to `<Archive>/.gibiomatic/trash/<date>-<id6>/`, with a `.trash.json` saying which book and which path it came from. Nothing is deleted; the previous `metadata.json` goes to the history.
- **2026-10-17 · F1: creating a library in a folder with files asks for confirmation (user decision).** Hidden and system files (`desktop.ini`, `.DS_Store`) don't count.
- **2026-10-17 · F1: Inbox queue in the local index.** The queue (each file's state, analysis, decision) lives in `inbox_items` in the SQLite under `%LOCALAPPDATA%`, as the SPEC asks. It is per machine; rebuilding the index doesn't erase the queue. Items interrupted when the app closes go back to the queue on the next start; the "paused" state is remembered too. A single worker processes one file at a time, analyses first and imports after.
- **2026-10-17 · F1: verified copy.** The original is copied to a `.part` in the book's folder, with the SHA-256 computed during the copy; it only gets its final name if the hash matches the analysis. If the file changed between the analysis and the copy, the import fails and nothing stays in the Archive.
- **2026-10-17 · F1: the same book in several formats.** In F1, "the same book" means an equal ISBN or an equal normalized title (no accents, punctuation, "Vol."/"#" or leading zeros). Two files from the same batch become one book, with the preferred format as the main original. For a book that already exists, the Inbox suggests "Replace" when the new format is preferred (or it is the same format and the current one was converted by Calibre), and "Keep both" otherwise. The existing metadata wins; the new file only fills in empty fields, and the folder is renamed if the publisher or series get filled in.
- **2026-10-17 · F1: initial title and kind.** Title: the embedded one; otherwise series and number ("Saga, Vol. 1" or "Saga #1"); otherwise the file name with `_` turned into spaces (without trying to split words run together, which is left for F2). Kind: the declared one (ComicInfo `Format`); otherwise `book` for a text EPUB, `issue` if the title has "Issue" or "#n", and `tpb` otherwise.
- **2026-10-17 · F1: PDF date.** The Info `CreationDate` is the file's date, not the publication's, and is ignored.
- **2026-10-17 · F1: "Needs review" = Poor score (< 60).** It applies to the filter and to the summary card, which in the prototype was called "Bad title or author". "Complete" = OK score (≥ 85).
- **2026-10-17 · F1: the "ALL CAPS" rule ported with `\b`.** `analyze.py` has a control character (backspace) where the `\b` should be, so the rule never fired in Python. The intent was ported; the other scores match the script (a test with the same cases).
- **2026-10-17 · F1: PDFium through our own P/Invoke.** `bblanchon.PDFium.*` binaries (Apache-2.0) and about 15 imported functions. The PDF is read through a callback (`FPDF_LoadCustomDocument`), which works with any path and doesn't load the whole file into memory. PDFtoImage was ruled out because it requires SkiaSharp 4, and Avalonia 12 uses 3.119. PdfPig was meant for F3 (lossless extraction), but turned out unnecessary (see the F3 decision).
- **2026-10-17 · F1: covers and thumbnails.** `cover.jpg` in the Archive up to 1200 px tall (JPEG 88). The grid thumbnails (240×360) live in `%LOCALAPPDATA%\GibiOMatic\thumbs\<library id>` and are recreated when the cover changes.
- **2026-10-17 · F1: grid virtualized by rows.** Avalonia 12 has no virtualizing grid panel; the grid is a virtualized list of rows, with the number of columns computed from the width. Narrow windows use container queries (narrower details panel, 2×2 summary).
- **2026-10-17 · Tests: the `GibiOMatic.Testing` project.** It generates synthetic PDFs, CBZs, CBRs (an uncompressed RAR 4 writer) and EPUBs inside the tests; it replaces the `tests/Shared` folder.
- **2026-10-17 · App icon.** `Assets/gibiomatic.ico` (16 to 256 px, PNG inside the ICO) generated from the sidebar logo by `tools/IconGen` (outside the solution; run with `dotnet run --project tools/IconGen`). Used as the executable's icon (`ApplicationIcon`) and the window's.
- **2026-10-17 · F2: identification after import (user decision).** Import stays fast; each imported book enters a background identification queue (index v3, `identifications` table), which respects the sources' limits. "Fetch metadata" in the Library re-queues the selected books or all the unreviewed ones, with a confirmation first (a batch operation).
- **2026-10-17 · F2: the cover stays the file's (user decision).** Identification doesn't replace `cover.jpg`; the Editor has "Change cover" and "Use page 1".
- **2026-10-17 · F2: ComicVine.** Key: the one stored in Settings (DPAPI) wins; otherwise `ComicVine:ApiKey` from the configuration (the `GIBIOMATIC_COMICVINE_KEY` variable, or user secrets in Debug). Limit: 1.2 s between calls and 190 per resource per hour; HTTP 420/429 and `status_code` 107 pause the source and retry. Responses are cached for 30 days (Open Library, 90) in `%LOCALAPPDATA%\GibiOMatic\cache`, without the key in the stored URL. The hourly counters don't survive an app restart; the cache and the automatic pause cover that case.
- **2026-10-17 · F2: algorithm.** Volume search by series name; short volumes (up to 12 issues) have all their issues listed in one call, long series only the issue with the number being looked for. The collected edition's number comes from the issue name ("Volume 11", "Vol. 1", "Book Two"). Scoring: title 0.30 (letter-pair similarity, which ignores spaces, so "houseofslaughter" matches), number 0.35, publisher 0.15, year 0.10, kind 0.05, exact name and subtitle 0.05 each; editions from translation-only publishers (Splitter, Urban Comics, Cross Cult…) lose 0.30. Details (credits, summary) only for the best candidate; the others when they are chosen in the Review. Cost ≈ 3 to 4 queries per book.
- **2026-10-17 · F2: Open Library and Google Books don't give credits.** Authors come without a role (the artist shows up as an author), so they don't become credits; credits come only from ComicVine, by role, without editors or designers (SPEC §8.2 item 4).
- **2026-10-17 · F2: "good field" in automatic approval.** An existing field is "good" when the quality score points out no problem with it (title, authors, date, series, publisher, ISBN). Equivalent values don't count as a conflict: "Image" = "Image Comics", "2022" = "2022-06", "saga vol1" ≈ "Saga, Vol. 1" (a title only conflicts if it is another book). Books already approved are never changed automatically; a new search for them goes to the Review.
- **2026-10-17 · F2: `oneShot` in `metadata.json`.** An optional field (`null` = undecided). It comes from the identification (a 1-issue volume without a collected-edition number) or from the Editor ("It is a one-shot"); Komga will use it for the one-shots folder.
- **2026-10-17 · F2: Editor.** Saving marks the book as reviewed (`matchedBy: manual`) by default; in a batch, the option starts off. In a batch, empty fields change nothing, title and credits aren't edited, and "Number in sequence" follows the order series → number → title. Undo = restore a version from the history, keeping the current list of files (originals don't move back). When the title changes, the original file is renamed to `{Title}.{ext}` (only the name, never the content).
- **2026-10-17 · F2: preview of the output names.** `GibiOMatic.Destinations.OutputNames` generates Komga's default names (`{Series}/{Series} v{nn} ({Year}).cbz`, one-shots in `_oneshots/`) and the Kindle's; F3 and F4 will use the same rules.
- **2026-10-17 · Review: candidate covers.** The cover comes with ComicVine's list of issues (`image.small_url`, no extra query), from Open Library (`cover.medium`) or from Google Books (`imageLinks`). Only HTTPS images from those hosts are downloaded, one at a time, and they live in `%LOCALAPPDATA%\GibiOMatic\cache\covers`. The file's cover appears next to the title for comparison. Candidates found before this change have no cover until "Search again".
- **2026-10-17 · Review: visible search.** "Search again" clears the previous result right away, shows "Searching “…”" with a progress bar and disables the actions; with no result, it says "Nothing found for “…”".
- **2026-10-17 · Review: replace the cover with the source's (user request).** It complements the decision to keep the file's cover: the Review table has a "Cover" row, always unchecked by default; when checked, on approval the app downloads the source's largest image (ComicVine `original_url`, Open Library `large`) and writes `cover.jpg`. Automatic approval never replaces the cover, and Editor → "Use page 1" goes back to the file's cover.
- **2026-10-17 · Review: pages.** Each file stores the page count counted on import (`files[].pages`); older books are counted on the spot. The Review shows "File: N pages" and the candidate's pages when the source provides them (Open Library and Google Books; the ComicVine API doesn't have that data).
- **2026-10-17 · Review: ComicVine link.** "Open on ComicVine" opens the search in the default browser (Avalonia has no free embedded browser); the user pastes the link of the right page (issue `4000-…` or volume `4050-…`) and the book becomes the candidate, with 100% confidence and the reason "chosen by you". A volume with several issues lists the ones closest to the book first.
- **2026-10-17 · Library: a one-book series** shows up as the book itself in the Series view (no stack and no "1 book").
- **2026-10-17 · F3: only reviewed books go to Komga (user decision).** A destination option (Advanced) includes the unreviewed ones too.
- **2026-10-17 · F3: summary and confirmation before generating in a batch (user decision).** The first sync and "Update now" show the plan (create, update, delete) and only write after "Confirm and generate". After the first confirmation, an "Automatic" destination updates on its own the copy of each book imported, approved or edited. The "confirmed" state lives in the index (`app_state`).
- **2026-10-17 · F3: old copies are deleted, but only the app's (user decision).** Index v4 has `destination_outputs` (destination, book, relative path, signature, date). Only files recorded there are deleted, and never outside the destination folder; folders left empty are removed. Removing a destination forgets the records and leaves the files in the folder.
- **2026-10-17 · F3: copy signature.** SHA-256 of the generator version, of the main original's SHA-256 and of the generated `ComicInfo.xml`. If the signature or the path changes → the copy is redone (written to a `.gibiomatic.tmp` and renamed) and the old one deleted.
- **2026-10-17 · F3: PDF extraction with PDFium itself, without PdfPig.** PDFium exposes the page objects (`FPDFPage_GetObject`, filters and raw image bytes), which is enough for the validated heuristic: a single DCTDecode RGB/gray image object covering the page (2 pt tolerance), with no rotation and no other objects → the JPEG bytes go straight into the CBZ. Otherwise, the page is rendered at the resolution of the largest image (between 1200 and 3200 px tall), JPEG 92. One dependency less.
- **2026-10-17 · F3: CBZ.** Pages `0001.jpg`… uncompressed (the images are already compressed), `ComicInfo.xml` at the end. A text EPUB goes as `.epub` when the "Include text books" option is on; otherwise it is left out.
- **2026-10-17 · F3: naming templates.** Tokens `{series}`, `{num}` (`v01` for collected editions, `#001` for single issues), `{number}`, `{year}`, `{title}`, `{publisher}`, `{oneshots}`; each `/` creates a folder; empty parts vanish along with the `()` around them; `:` becomes ` -`. Without a one-shots folder, each one-shot gets a folder with its own name. The Editor preview uses the templates of the first Komga destination.
- **2026-10-17 · F3: Komga API.** `GET /api/v1/libraries` (tests the address and key, lists the libraries and reads `oneshotsDirectory`) and `POST /api/v1/libraries/{id}/scan` after each sync that changed something. Authentication through the `X-API-Key` header; the key is stored with DPAPI (`destination-<id>`). The scan requires an administrator user; scan failures only go to the log.
- **2026-10-17 · F3: visible updates and per-destination history (user request).** During a sync, the destination card and detail swap the status for "Updating…", with the current book, "N of M" and a bar; "Update now" is disabled. Every copy created, updated or deleted, every error (with its message), the notice to Komga and each run's summary go to `destination_log` in the index (v5, up to 2000 lines per destination) and show up under "History" in the detail. The card turns red when the last run had errors. The technical details (exception stack) stay in the app log, `%LOCALAPPDATA%\GibiOMatic\logs\gibiomatic-YYYYMMDD.log` (14 days), opened by the "Open logs folder" button.
- **2026-10-17 · F3: pending automatic updates survive closing the app.** Each changed book enters the `destination_pending` table (index v6) before entering the in-memory queue and only leaves after its copies have been updated. When the library opens, the pending ones are processed first. If an automatic destination is unavailable (disconnected drive), the book stays pending for the next start. Background interface updates that fail go to the log and no longer bring down the app.
- **2026-10-17 · Inbox: imported files leave the list (user request).** Once imported, the file disappears from the Inbox list and only counts in the summary ("Import finished: …"). Skipped and failed ones stay in the list until "Clear finished". The records of imported files are deleted from the index when the library opens.
- **2026-10-18 · F3: faster PDF → CBZ.** (1) As in the reference script, the page's JPEG also goes without recompression when the color space is ICCBased/CalRGB/CalGray and the JPEG has 1 or 3 components (read from the SOF header); before, only DeviceRGB/DeviceGray passed, and Humble's PDFs mark their pages as ICCBased. (2) PDFium renders one page at a time (it isn't thread-safe), but the JPEG compression of the rendered pages runs in parallel, with up to 4 pages in flight (~25 MB each). Measured on two real PDFs from the collection: 48 s → 33 s and 41 s → 26 s. The rest of the time is rendering the pages with vector lettering (thousands of paths per page), which has to be done. The generator version didn't change: copies already generated aren't redone.
- **2026-10-18 · F3: automatic updates in batches, with one scan at the end.** Changed books enter the pending list, and a single automatic run waits in the queue: it waits 1.5 s to gather nearby changes (batch editing) and then takes all the pending books together ("3 of 10"). Changes arriving during the run show up as "+N" and go in the next one. The scan request to Komga only goes out when no other run is waiting (before, it was one per book). The progress also carries the current book's fraction, shown in a second bar.
- **2026-10-18 · Destinations: going back to the page shows the list.** Leaving the Destinations page closes the destination or the wizard that was open; clicking in the sidebar still opens the destination directly.
- **2026-10-18 · F3.5: a reader inside the app (user request).** A new phase between F3 and F4. MOBI/AZW3 stay in the backlog. Text EPUB uses `Avalonia.Controls.WebView` (open source in Avalonia 12, the system's engine: WebView2/Chromium on Windows), instead of an embedded Chromium (CEF): no +150 MB in the app, security updates through the system, and CefGlue has no version for Avalonia 12.
- **2026-10-18 · F3.5: reader security.** EPUB: content served from inside the file, without JavaScript, with requests outside the book blocked and external links doing nothing. PDF: the `bblanchon.PDFium` package (without the `.V8` suffix) is built without V8 and without XFA, and the app only uses the reading and rendering functions; it never initializes the form environment (`FPDFDOC_InitFormFillEnvironment`), so no PDF action (JavaScript, links, opening files, attachments) runs. The remaining risk is a bug in the PDF reader itself with a malicious file; keeping PDFium up to date covers that.
- **2026-10-18 · F3.5: the reader in its own window.** Each book opens in a separate window (opening the same file again brings its window to the front), so the reader can sit next to the Review while the candidates are compared. F11 toggles full screen; in full screen, the toolbar and the thumbnails come back when the pointer reaches the edges. Esc leaves full screen or closes the window.
- **2026-10-18 · F3.5: pages.** Only the page on screen and its neighbors are kept ready (a 10-page cache), rendered at the size they are shown; zooming or a larger window renders again, sharper. An image is never enlarged beyond its own size; a PDF page is rendered at the requested size (up to 6000 px). Actual size for a PDF = 96 dpi. A solid RAR can only be read from the start: the pages go into memory once, in the background, in the order they arrive. Thumbnails are rendered when the strip shows them, the most recent first.
- **2026-10-18 · F3.5: two-page spread.** The cover stays alone; then the pages go in pairs (2–3, 4–5…). A wide page (a spread scanned as a single image) stays alone and the pairing continues after it. The sizes are read from the headers in the background; until then, every page counts as portrait.
- **2026-10-18 · F3.5: what the reader stores.** The position (page, or chapter in a text EPUB) and the reading direction live in the index, per book (v7, `reading_state`), together with the file name: another file of the same book starts from the beginning. Fit, two-page spread, thumbnails and text size apply to every book and live in the settings (`reader`).
- **2026-10-18 · F3.5: text EPUB.** An EPUB is text when it isn't *fixed layout* and has fewer than 0.8 images per table-of-contents document (the same rule as import); otherwise it opens as pages. The content is served by a minimal HTTP server on 127.0.0.1 (random port, a random token in each address, GET only), straight from the file, because the WebView can't serve content from inside the app. The dark theme and the text size are a reader stylesheet applied last; changing the size reloads the chapter.
- **2026-10-18 · F3.5: reading status.** It lives in the index (v8: `total`, `started` and `read_at` in `reading_state`), per machine, like the position; rebuilding the index doesn't erase it, because only the book tables are redone. Three statuses that don't overlap: **reading** (started and not read), **read** and **unread** (neither); that is what the filters show. "Started" requires more than 5 different pages seen in one session (in a text EPUB, more than 1 chapter), or every page of a short book; jumping with End or through the thumbnails to see the credits doesn't count. "Read" = the last page was shown after the book had been started (in this session or before); reopening a book that stopped on the last page doesn't count again. Marking as **unread** also forgets the position and "started"; **Clear progress** forgets only the position and "started". The "Continue reading" strip only shows with the All filter, without a search and outside a series, and it updates without redrawing the grid while a book is read beside it.
- **2026-10-18 · F3.5: slow PDFs in the reader.** Some Humble PDFs have huge scanned pages (a 1 GB volume), and PDFium takes 1 to 6 s per page, whatever the requested size, because the time goes into decoding the image. So the page on screen has priority: a new request cancels whatever the previous one was still waiting for; thumbnails and reading the sizes only run when no page is waiting; a page rendered ahead of time isn't rendered again. The thumbnail of each page shown comes from its own rendering. In a "slow" book (average above 700 ms per page), thumbnails only come from pages already rendered. While the page isn't ready, "Loading page…" shows over the previous one.
- **2026-10-18 · F3.5: pages prepared in the background (the user's idea).** After the page on screen appears, a queue renders, one at a time, the next 2 pages, the previous one, 2 more after and 1 more before (on page 10: 11, 12, 9, 13, 14, 8). The next page in the queue is chosen again after each one, so turning the page replans the queue by itself, and the page on screen always jumps ahead. Up to 4 pages after the screen and 3 before stay in memory; the rest is released. A page already rendering can't be interrupted (PDFium doesn't abort midway): it finishes and is kept if it is still within the window. With ~1600 px pages, the window costs about 60 MB.
- **2026-10-18 · F3.6: universes.** ComicVine has no "universe" (concepts and story arcs are too irregular to fill in automatically), so the field is manual: a `universes` list in `metadata.json`, because a series can be in more than one (publishing line and crossover event). Names are compared case-insensitively, and the first spelling used in the library wins. A comma separates universes (it is the `SeriesGroup` separator), so "A, B" typed in the Editor becomes two. In a batch, the Editor only shows the universes all the books have, and applies the difference (what was removed and what was added) to each book. Books without a universe don't change their ComicInfo, so the Komga copies don't become outdated. With a universe, the copy is redone on the next sync, to carry the `SeriesGroup`.
- **2026-10-18 · F4: prepare first, send later (user decision).** The Kindle works in two steps: the chosen books are converted in the background into a local staging folder, without the device connected; sending happens when the user connects it and confirms. The prepared copy is deleted after it is sent. **The app never deletes anything from the Kindle on its own**: removing a book from the list doesn't remove it from the device. Deleting is manual only, in a mini Kindle manager, with confirmation.
- **2026-10-18 · F4: KCC.** KCC is an external process and **doesn't ship with the app**: the published executable includes PyMuPDF (AGPL) and 7-Zip. The app looks for the KCC it downloaded itself (`%LOCALAPPDATA%\GibiOMatic\tools\kcc`), one picked by hand or one on the PATH. "Download KCC" fetches `tool_cli_c2e` 12.0.0 from the official GitHub release and checks the SHA-256 pinned in the code. Findings in the KCC 12 code: without `--forcecolor` it converts everything to gray, even with the `KCS` profile; from the command line it only looks for `kindlegen` on the PATH, so the app puts the Kindle Previewer folder (`lib\fc\bin`) on the process's PATH; and it exits with code 0 even when KindleGen fails, so success means the `.mobi` exists and there is no error line. The progress comes from the steps it prints. A 45-minute timeout per book. If KCC splits a large book into several parts, that is treated as an error (not supported yet).
- **2026-10-18 · F4: the Kindle file.** KCC produces a MOBI that is also AZW3 ("dual") and uses the `.mobi` extension for compatibility, so the name on the Kindle is `{Series} v{Number} ({Year}).mobi`. KCC's input is a temporary CBZ built from the original by the same `CbzBuilder` as Komga; title and author (writers, or artists) go through `-t` and `-a`.
- **2026-10-18 · F4: preparing and sending.** The Kindle destination reuses the destinations mechanism: the "folder" is the staging one (`%LOCALAPPDATA%\GibiOMatic\kindle\<id>`), the books are the chosen ones, preparation is automatic and starts out confirmed (it only writes to the local folder). Chosen books get in even without review (the choice is explicit). What was sent is recorded in `.sent/<bookId>.json` in the staging folder (file on the device, content, date): with that, a sent book counts as done after the local copy is deleted, a metadata change prepares it again ("ready · replaces"), and the manager knows which files on the device belong to the app. When sending, a file with the same name that the app didn't send is **never** replaced; one the app sent is replaced and its `.sdr` folder (notes and position) stays. The file is written under a temporary name and renamed, so the Kindle doesn't index half a book; if the device won't rename, it is written again under the final name. The connection is opened only during each operation.
